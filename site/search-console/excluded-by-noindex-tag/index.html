Excluded by ‘noindex’ tag

When Google tried to index the page, it found a noindex directive and left the page out. Google's help puts it plainly: if you do not want the page indexed, all is well; if you do, remove the directive.

Updated 28 November 2026 · Search Console guide

On this page

  1. What the status means
  2. Where a noindex hides
  3. How to remove it
  4. Mistakes to avoid

What the status means

Google crawled the page and found an instruction not to index it. This is the reliable way to keep a page out of Google, so for thank-you pages, internal search or staging copies it is exactly right. The trouble starts when a page you want in search carries it.

Where a noindex hides

  • A meta tag in the HTML head: <meta name="robots" content="noindex"> or name="googlebot".
  • An HTTP header: X-Robots-Tag: noindex, set by the server, a CDN rule or a framework. It does not show in the page source, only in the response headers.
  • A CMS or plugin setting: a site-wide "discourage search engines" switch left on after launch, or a per-page SEO plugin setting.
  • JavaScript that adds or changes the robots meta tag after the page loads.

How to remove it

  1. Inspect an example URL with URL Inspection's live test; it says whether indexing is allowed and why not.
  2. Check the headers: curl -I https://example.com/page and look for X-Robots-Tag.
  3. Remove the directive at its source (template, plugin, server or CDN rule).
  4. Make sure the page is not blocked in robots.txt; Google has to crawl it again to see the noindex is gone.
  5. Request indexing for the key pages and press Validate fix. Google's help says validation typically takes up to about two weeks, and sometimes much longer.

Mistakes to avoid

  • Combining noindex with a robots.txt block: Google cannot crawl the page, so it never sees the noindex.
  • Using noindex to choose between duplicates. Use a canonical instead; see Duplicate without user-selected canonical.

Related guides

  • Soft 404

    The page answers 200 OK but looks like an error or an empty page to Google. Return a real 404, or give the page real content.

  • Blocked due to other 4xx issue

    The server answered with a 4xx code that has no status of its own in the report, such as 400 Bad Request. Find which code and why.

  • Blocked by robots.txt

    Your robots.txt stops Googlebot from crawling the URL. Fine for private areas, a problem when it blocks pages you want found.

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.
