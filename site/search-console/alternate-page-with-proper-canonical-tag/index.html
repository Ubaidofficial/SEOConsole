Alternate page with proper canonical tag

This page has a rel="canonical" tag pointing to another URL, and Google agreed with it, so Google indexes the other URL instead. Google's own help calls this usually a good sign. It is only a problem when the canonical tag points somewhere it should not.

Updated 28 November 2026 · Search Console guide

On this page

  1. What the status means
  2. When it is normal
  3. When it is a problem
  4. How to fix a wrong canonical
  5. Statuses that look similar

What the status means

In Search Console's Indexing → Pages report, this reason means the page declares another URL as its canonical, Google followed that, and so this alternate URL is not indexed on its own. The canonical URL is the one that appears in search.

The question to ask is not "why isn't this page indexed?" but "should this page point somewhere else at all?" If yes, you can ignore the entry. If no, the canonical tag is wrong.

When it is normal

  • URLs with tracking, sorting or filter parameters that point to the clean URL.
  • AMP pages or a separate mobile site (m.example.com) pointing to the main version.
  • Product variants (colour, size) that point to one main product page.
  • Content you republished on purpose with a canonical to the original.

A steady number of these entries on a site with parameters or variants is expected. It does not hold the canonical pages back.

When it is a problem

Watch for pages that should rank on their own showing up here. Usual causes:

  • A template sends every page's canonical to the home page or to one category page, often after a theme, plugin or framework change.
  • Paginated pages all point to page 1, so products or posts linked only from page 2 onward lose their path into the index.
  • The canonical uses the wrong host or protocol, such as a staging domain or http://, left over from a migration.
  • Language versions point to one language instead of to themselves (with hreflang between them).

A sudden jump in this count right after a release is the clearest sign of a template bug. Open a few example URLs and look at the canonical in the page source.

How to fix a wrong canonical

  1. Give every page that should rank a self-referencing canonical with its own absolute URL.
  2. Make sure each canonical target returns 200, is not redirected, is not noindex and is not blocked in robots.txt.
  3. Keep the sitemap and internal links pointing to the canonical URLs, so every signal agrees.
  4. Inspect a fixed URL with URL Inspection, then press Validate fix in the report. Google has to recrawl before the status changes, and gives no fixed time for that.
