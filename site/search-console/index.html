Search Console indexing errors, explained

Search Console's Indexing → Pages report, its Sitemaps report and URL Inspection explain why Google did not index some of your pages. Many of these messages are not errors at all. Each guide says what the message means, when it needs work and what to do about it, with links to Google's own documentation.

Updated 28 November 2026 · 11 guides

Duplicates, canonicals and redirects

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.

  • Alternate page with proper canonical tag

    The page points to another URL as its canonical and Google agreed. Usually fine, unless the tag points somewhere it should not.

  • Page with redirect

    The URL redirects somewhere else, so Google indexes the target, not this URL. A problem only when your own links and sitemap still use it.

Crawling, discovery and sitemaps

  • Discovered – currently not indexed

    Google knows the URL exists but has not crawled it yet. Common on new sites, large sites and pages with few internal links.

  • Crawled – currently not indexed

    Google fetched the page and decided not to index it for now. Usually about how useful and distinct the page is.

  • Sitemap could not be read

    Search Console could not fetch or parse your sitemap. Check it loads for Googlebot, is valid XML and is not blocked.

  • No referring sitemaps detected

    URL Inspection found no processed sitemap that lists this URL. Often only timing, sometimes a URL that differs from the one in the sitemap.

Blocked pages and errors

  • Soft 404

    The page answers 200 OK but looks like an error or an empty page to Google. Return a real 404, or give the page real content.

  • Blocked due to other 4xx issue

    The server answered with a 4xx code that has no status of its own in the report, such as 400 Bad Request. Find which code and why.

  • Blocked by robots.txt

    Your robots.txt stops Googlebot from crawling the URL. Fine for private areas, a problem when it blocks pages you want found.

  • Excluded by ‘noindex’ tag

    The page carries a noindex directive, in a meta tag or an HTTP header. Often a leftover from staging or a plugin setting.
