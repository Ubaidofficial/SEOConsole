Soft 404

The page answers with 200 OK, but to Google it looks like an error page or a page with nothing on it. Google's help recommends returning a real 404 for pages that are truly gone, and adding real content to pages that are not.

Updated 28 November 2026 · Search Console guide

On this page

  1. What a soft 404 is
  2. Common causes
  3. How to fix it
  4. How to check

What a soft 404 is

A normal "not found" page returns the HTTP status 404 (or 410). A soft 404 is a page that tells visitors something is missing, or shows almost nothing, while the server still says 200 OK. Google then treats it as an error and does not index it.

Common causes

  • Custom error pages that return 200, common in single-page apps and some CMS themes.
  • Empty listings: a category, search or tag page with no items, showing "No results".
  • Out-of-stock or expired items whose page now says "no longer available" and little else.
  • Redirecting many old URLs to the home page or another unrelated page; Google can treat those as soft 404s too.
  • Content that does not render for Googlebot, leaving an almost empty page.

How to fix it

  • Gone for good: return 404 or 410.
  • Moved: 301-redirect to the closest equivalent page, not to the home page.
  • Still valid: give the page real content, such as items, a description or alternatives, so it is clearly not an error.
  • Single-page apps: make the server answer with a real 404 status for unknown routes, or add a noindex to the client-side error view.

How to check

Run the URL through URL Inspection's live test and look at the HTTP response and the rendered page. Then press Validate fix; Google's help says validation typically takes up to about two weeks, and sometimes much longer.

SEOConsole also lists the not-found addresses visitors actually reach, read from GA4, including ones AI assistants send people to, so you can redirect the ones that matter.

Related guides

  • Blocked due to other 4xx issue

    The server answered with a 4xx code that has no status of its own in the report, such as 400 Bad Request. Find which code and why.

  • Blocked by robots.txt

    Your robots.txt stops Googlebot from crawling the URL. Fine for private areas, a problem when it blocks pages you want found.

  • Excluded by ‘noindex’ tag

    The page carries a noindex directive, in a meta tag or an HTTP header. Often a leftover from staging or a plugin setting.

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.
