Blocked by robots.txt

Your site's robots.txt stops Googlebot from crawling the URL. Google's help adds a warning: a robots.txt block does not guarantee the page stays out of the index. To keep a page out of Google, allow crawling and use noindex instead.

Updated 28 November 2026 · Search Console guide

On this page

  1. What the status means
  2. Is the block intended?
  3. How to unblock a page
  4. How to keep a page out instead

What the status means

A Disallow rule in /robots.txt matches the URL for Googlebot, so Google does not fetch it. It can still learn the URL exists from links, which is why a blocked URL sometimes appears in search without a description; Search Console reports that case separately as Indexed, though blocked by robots.txt.

Is the block intended?

  • Usually intended: admin areas, carts and checkouts, internal search results, endless filter combinations.
  • Usually a mistake: a Disallow: / left over from staging, a rule that matches more than intended (such as Disallow: /p also blocking /pricing), or blocked CSS and JavaScript that pages need to render.

How to unblock a page

  1. Open Settings → robots.txt in Search Console to see the file Google last fetched, and check which rule matches the URL.
  2. Remove or narrow the rule. Rules match from the start of the path, so be specific.
  3. Run the URL through URL Inspection's live test and confirm Crawl allowed: Yes.
  4. Press Validate fix. Google's help says validation typically takes up to about two weeks, and sometimes much longer.
User-agent: *
Disallow: /cart/
Disallow: /search
Sitemap: https://example.com/sitemap.xml

How to keep a page out instead

If the goal is "not in Google", robots.txt is the wrong tool. Allow crawling and add <meta name="robots" content="noindex"> or an X-Robots-Tag: noindex header, so Google can read the instruction. See Excluded by ‘noindex’ tag.

SEOConsole reads each site's robots.txt every day and logs every change in the site's change log, so a rule that suddenly blocks half the site shows up the day it ships.

Related guides

  • Soft 404

    The page answers 200 OK but looks like an error or an empty page to Google. Return a real 404, or give the page real content.

  • Blocked due to other 4xx issue

    The server answered with a 4xx code that has no status of its own in the report, such as 400 Bad Request. Find which code and why.

  • Excluded by ‘noindex’ tag

    The page carries a noindex directive, in a meta tag or an HTTP header. Often a leftover from staging or a plugin setting.

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.
