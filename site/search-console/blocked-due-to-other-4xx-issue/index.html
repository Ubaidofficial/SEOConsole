Blocked due to other 4xx issue

When Googlebot requested the URL, your server answered with a 4xx error that none of the report's other reasons covers. Google's help suggests debugging the page with the URL Inspection tool, which shows the actual response.

Updated 28 November 2026 · Search Console guide

On this page

  1. What the status means
  2. Find the exact code
  3. Common causes
  4. How to fix it

What the status means

The Page indexing report has separate reasons for the common client errors, such as Not found (404), Blocked due to unauthorized request (401) and Blocked due to access forbidden (403). This one collects the other 4xx answers. Google's crawler documentation says it treats 4xx errors, except 429, as content that does not exist, so these URLs are not indexed.

Find the exact code

  1. Open an example URL from the report and run Test live URL in URL Inspection.
  2. Look at the HTTP response, or request the URL yourself: curl -I https://example.com/page.
  3. Check your server, CDN or firewall logs for Googlebot requests to that URL around the crawl date.

Common causes

  • 400 Bad Request from malformed URLs: broken encoding, stray characters, URLs built by JavaScript or copied from somewhere else.
  • A firewall, CDN or bot-protection rule that answers Googlebot with an unusual 4xx code.
  • Old API, form or download endpoints that are linked somewhere and refuse a plain GET.
  • Size or method limits on the server, such as 413 or 405.

How to fix it

  • If the page should be indexed, make it return 200 for a normal GET without cookies, logins or special headers.
  • If the URL should not exist, return a plain 404 or 410, and remove the links or sitemap entries that point to it.
  • If a security rule is the cause, allow verified Googlebot rather than switching protection off.

Related guides

  • Soft 404

    The page answers 200 OK but looks like an error or an empty page to Google. Return a real 404, or give the page real content.

  • Blocked by robots.txt

    Your robots.txt stops Googlebot from crawling the URL. Fine for private areas, a problem when it blocks pages you want found.

  • Excluded by ‘noindex’ tag

    The page carries a noindex directive, in a meta tag or an HTTP header. Often a leftover from staging or a plugin setting.

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.
