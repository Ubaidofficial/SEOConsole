Sitemap could not be read

Search Console could not fetch or process your sitemap file. Google's Sitemaps report help lists the usual reasons: the file is blocked by robots.txt, returns an error such as 404, or the server had a temporary problem. Some of these clear up on their own.

Updated 28 November 2026 · Search Console guide

On this page

  1. What the status means
  2. Test it like Googlebot
  3. Common causes
  4. Fix and resubmit

What the status means

In Indexing → Sitemaps, a status of Couldn't fetch on the main list means Google could not retrieve the sitemap file itself. Google's help says it retries for a few days and then stops if the sitemap stays unavailable or has critical errors. It also notes that some of these errors are temporary, so a fresh submission can briefly show this status before Google has processed it.

Test it like Googlebot

  1. Open the sitemap URL in a private browser window. It should load without a login and show XML.
  2. Put the sitemap URL into URL Inspection and run Test live URL. Google's help says to look for Crawl allowed: Yes and Page fetch: Successful.
  3. Check the response: curl -I https://example.com/sitemap.xml should return 200.

Common causes

  • robots.txt blocks the sitemap path.
  • Wrong address: the submitted URL returns 404, or redirects somewhere unexpected.
  • Firewall or bot protection that challenges Googlebot, so it gets a challenge page instead of XML.
  • Invalid XML: an HTML error page served as the sitemap, a stray character before <?xml, or unescaped & in URLs.
  • URLs from another host than the property, such as a www. sitemap listing bare-domain URLs.
  • Too large: Google's sitemap limits are 50,000 URLs or 50 MB uncompressed per file; split larger ones with a sitemap index.

Fix and resubmit

Fix the cause, confirm the live test passes, then resubmit the sitemap in the Sitemaps report. Submitting is a request: Google reads the file on its own schedule.

Related guides

  • Discovered – currently not indexed

    Google knows the URL exists but has not crawled it yet. Common on new sites, large sites and pages with few internal links.

  • Crawled – currently not indexed

    Google fetched the page and decided not to index it for now. Usually about how useful and distinct the page is.

  • No referring sitemaps detected

    URL Inspection found no processed sitemap that lists this URL. Often only timing, sometimes a URL that differs from the one in the sitemap.

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.
