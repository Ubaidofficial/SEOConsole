Discovered – currently not indexed

Google knows the URL exists, from a link or your sitemap, but has not crawled it yet. Google's help says that it usually wanted to crawl, but rescheduled because crawling then was expected to overload the site. On new sites and on large sites with many low-value URLs, this list can stay long for a while.

What the status means

In Indexing → Pages, this reason means Google has found the URL but has not fetched it. In URL Inspection, such a page typically has no last crawl date. Nothing is wrong with the page itself yet: Google has not looked at it.

New pages often sit here for a short time and then move on. It becomes worth acting on when important pages stay here for weeks, or the list keeps growing.

Discovered vs crawled

StatusHas Google fetched the page?Where to look
Discovered – currently not indexedNoCrawling: internal links, crawl demand, server speed
Crawled – currently not indexedYes, and decided not to index it for nowThe page: how useful and distinct it is

Common causes

  • A new or small site that Google does not crawl often yet.
  • Too many URLs for the value they add: filters, tags, internal search results or parameter combinations that multiply the number of pages Google could crawl.
  • Few internal links: the URL is only in the sitemap, or only reachable many clicks deep.
  • Slow or failing responses: Google crawls less when the server is slow or returns errors. Check Settings → Crawl stats in Search Console.

What helps

  1. Link to the page from pages Google already crawls, such as the home page, a hub page or related articles, with descriptive anchor text.
  2. Keep the sitemap accurate: only canonical, indexable URLs that return 200, with a lastmod that changes only when the page really changes.
  3. Reduce low-value URLs: consolidate thin variants, stop linking to endless filter combinations, and keep internal search results out of the crawl.
  4. Make the server answer fast and reliably, and fix spikes of 5xx errors in Crawl stats.
  5. Request indexing for the few pages that matter most with URL Inspection. Search Console limits how many requests you can make, so save them for important URLs.

Google's Indexing API is documented for job-posting and livestream pages only, so it is not a shortcut for ordinary pages. For Bing and other engines that support it, IndexNow tells them about new URLs immediately; Google does not use IndexNow.

What does not help

  • Resubmitting the same sitemap again and again. Google reads it on its own schedule.
  • Requesting indexing for hundreds of URLs one by one, or for pages with little of their own to offer.
  • Blocking the URLs in robots.txt to "save crawl budget" when you actually want them indexed.

    Search Console could not fetch or parse your sitemap. Check it loads for Googlebot, is valid XML and is not blocked.

    URL Inspection found no processed sitemap that lists this URL. Often only timing, sometimes a URL that differs from the one in the sitemap.

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.
