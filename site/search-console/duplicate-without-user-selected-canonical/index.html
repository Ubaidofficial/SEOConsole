Duplicate without user-selected canonical

Google decided this page is a copy of another URL, found no canonical tag saying which version you prefer, and chose the other one to show in search. Most of the time that is Google working as intended. It becomes a problem when Google picks the wrong page.

Updated 28 November 2026 · Search Console guide

On this page

  2. Check which URL Google chose
  3. Common causes

What the status means

You find this status in Search Console under Indexing → Pages, in the list of reasons why pages are not indexed. Google's help page describes it this way: the page is a duplicate of another page, it does not declare a canonical, and Google has chosen the other page as the canonical. Google does not show this URL in search; it shows the canonical instead.

That is not a penalty. If two URLs carry the same content, you want one of them in search, not both. The status only tells you that Google made the choice for you.

Fine: Google chose the URL you would have chosen, such as the clean URL over one with tracking parameters.
A problem: Google chose a URL you do not want people to land on, or it merged two pages that are meant to rank separately.

Check which URL Google chose

  1. In the Pages report, open Duplicate without user-selected canonical and click an example URL.
  2. Choose Inspect URL. In the URL Inspection result, open Page indexing.
  3. Compare User-declared canonical (here it is empty, which is why the page has this status) with Google-selected canonical.

Google's help notes that the live test does not check duplicate status, so read the indexed result, not only the live test.

Common causes

  • URL parameters: the same page reachable with ?utm_source=, ?sort=, ?ref= or session IDs.
  • Host and protocol variants: both http:// and https://, or both www. and the bare domain, answer with the page instead of redirecting.
  • Trailing slashes and case: /pricing and /pricing/, or /Blog and /blog, both return the page.
  • Near-identical templates: product variants, location pages or tag archives with little text of their own.
  • Print, AMP or feed versions without a canonical back to the main page.

How to fix it

If Google's choice is right, you can leave it: nothing is broken. Declaring the canonical yourself still helps, because it turns Google's guess into your instruction. If the choice is wrong, use these signals, which Google's canonical documentation lists from strong to weak:

  1. 301 redirects from the duplicate to the preferred URL, when the duplicate does not need to exist (old URLs, host and protocol variants).
  2. A rel="canonical" link in the <head> of each duplicate, with the absolute preferred URL, plus a self-referencing canonical on the preferred page.
  3. Consistent internal links: link to the preferred URL everywhere, without parameters.
  4. A sitemap that lists only the preferred URLs. Google calls sitemap inclusion a weak signal on its own, so use it together with the two above.

If two pages are meant to rank on their own, the fix is the opposite: make them clearly different, with their own title, main text and purpose, and give each a self-referencing canonical.

<!-- on https://example.com/shoes?sort=price -->
<link rel="canonical" href="https://example.com/shoes">

What not to do

  • Do not block duplicates in robots.txt. Google's documentation says not to use robots.txt for canonicalization: a blocked URL cannot show its canonical tag, and it can still be indexed without its content.
  • Do not use noindex to pick the canonical. Google advises against it; use the signals above.
  • Do not use the URL removal tool for this. It hides every version of the URL from search, not just the duplicate.
  • Do not keep pressing Request Indexing on the duplicate. Google will index the canonical, not the copy.

After the fix

Google has to recrawl the pages before the report changes. Press Validate fix in the report to ask Google to check the listed URLs; Google's help says validation typically takes up to about two weeks, and sometimes much longer. Spot-check a few URLs with URL Inspection to confirm the Google-selected canonical is now the one you declared. Google still chooses the canonical from all its signals, so it can occasionally keep a different one.

Related guides

  • Alternate page with proper canonical tag

    The page points to another URL as its canonical and Google agreed. Usually fine, unless the tag points somewhere it should not.

  • Page with redirect

    The URL redirects somewhere else, so Google indexes the target, not this URL. A problem only when your own links and sitemap still use it.

  • Discovered – currently not indexed

    Google knows the URL exists but has not crawled it yet. Common on new sites, large sites and pages with few internal links.

  • Crawled – currently not indexed

    Google fetched the page and decided not to index it for now. Usually about how useful and distinct the page is.
