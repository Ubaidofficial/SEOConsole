Google Search Console MCP server

SEOConsole includes a Model Context Protocol server, so Claude, ChatGPT, Claude Code, Cursor and other MCP apps can answer questions from your own Search Console data, for every property and Google account you connect, with Bing, GA4, Tag Manager and Clarity beside it. It is free and open source, and it reads until you allow it to change anything.

What you can ask

  • “What should I fix first across all my sites?” (get_action_queue)
  • “Why did clicks drop on this site last week?” (get_drop_diagnosis, get_trends)
  • “Which searches sit just off page one, and what would moving them up be worth?” (get_opportunities)
  • “Which sitemap pages have never appeared in search, and why?” (get_sitemap_coverage, get_indexing_status)
  • “Does Tag Manager send to the right GA4 property?” (get_tracking_health)
  • “How much traffic do AI assistants send us?” (get_ai_traffic)

How it differs from calling the API live

A server that passes every question straight to the Search Console API is limited to what that API returns on the spot. SEOConsole syncs your data first and the agent reads from that store:

  • History past 16 months: Search Console keeps about 16 months; SEOConsole keeps everything it has synced from the day you connect. It cannot recover data Google no longer has.
  • Every site at once: all properties and Google accounts in one place, so one question can cover your whole portfolio.
  • Findings, not only rows: a ranked to-do list, opportunities sized on each site's own click curve, drop diagnosis, alerts and a weekly digest.
  • More than Google: Bing Webmaster data, GA4, Tag Manager, Clarity and Core Web Vitals beside Search Console.
  • An indexing toolkit: stored URL Inspection results, sitemap checks, IndexNow and Bing submission, and a request list for the pages worth asking Google about.

Connect your AI app

Your MCP address is your SEOConsole address plus /api/mcp, for example https://app.seoconsole.app/api/mcp. The MCP page in your dashboard shows yours.

Claude

  1. In Claude, open Settings → Connectors and choose Add custom connector.
  2. Name it SEOConsole and paste your MCP address.
  3. Click Add, then Connect. Sign in on your SEOConsole, pick the sites Claude may read, and Allow.

Claude Code

claude mcp add --scope user --transport http \
  seoconsole https://app.seoconsole.app/api/mcp

Use your own address, then type /mcp in Claude Code and sign in.

ChatGPT

  1. Once, on your server: add ChatGPT's callback address to MCP_OAUTH_REDIRECTS (the MCP page explains how).
  2. In ChatGPT, turn on Developer mode under Settings → Apps & Connectors → Advanced, then create a connector.
  3. Paste your MCP address, choose OAuth, then sign in on your SEOConsole and Allow.

This needs a paid ChatGPT plan with developer mode. OpenAI moves these menus often, so check their help if a label differs.

Cursor, Codex, Windsurf and others

{
  "mcpServers": {
    "seoconsole": {
      "url": "https://app.seoconsole.app/api/mcp",
      "headers": { "Authorization": "Bearer osc_YOUR_KEY" }
    }
  }
}

Sign in if the app offers it, or create a key on the MCP page and use this shape.

Permissions and safety

  • Reads by default. The 26 tools that change things refuse unless you gave that connection the submit level, which is off by default.
  • Deleting is a separate level, also off by default. It adds only two things: removing a sitemap from Search Console and discarding queued submissions, each after a second, confirming call.
  • What nothing can do: delete your search data, connect accounts, or touch keys and passwords.
  • Audit log and limits: every change is logged; live URL inspections are rate-limited and have a daily budget per key.
  • Scoped per site: when you connect with OAuth you choose which sites the app may read.

FAQ

Is the Search Console MCP server free?

Yes. It is part of SEOConsole, which is open source under the AGPL-3.0 licence and free to self-host with every feature. A hosted plan at $9 a month is planned but not open yet.

Which AI clients work with it?

Claude’s custom connector works with one-click sign-in, and Claude Code works with a single command. Any MCP client that speaks HTTP with a bearer token or OAuth should work, but only Claude has been confirmed.

Can the agent change my sites?

Only if you allow it. A connection reads by default. A key needs the submit level before it can send URLs or sitemaps, and deleting is a separate level. Every change is written to an audit log.

Where does my data go?

Your search data stays in a SQLite file on the server you run SEOConsole on. Whatever an agent reads is sent to that agent’s provider, so connect only agents you trust with that data.

Does it need my Search Console password?

No. You connect Google once in SEOConsole with Google’s own sign-in, and the AI app signs in to your SEOConsole with OAuth or a key you create. The agent never sees your Google credentials.

Run it on demo data first

Start SEOConsole with its built-in demo data in three commands, connect your AI app to it and ask away. When you like what you see, connect your own Google account.

Search Console guides

  • Duplicate without user-selected canonical

    Google treats the page as a copy of another URL and picked that one to show, because you did not say which you prefer.

  • Alternate page with proper canonical tag

    The page points to another URL as its canonical and Google agreed. Usually fine, unless the tag points somewhere it should not.

  • Discovered – currently not indexed

    Google knows the URL exists but has not crawled it yet. Common on new sites, large sites and pages with few internal links.
